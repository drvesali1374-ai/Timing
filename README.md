# زمان‌سنجی صنعتی — نرم‌افزار مطالعات زمان استاندارد خطوط تولید

نرم‌افزار تحت وب برای مطالعات زمان (Time Study) در صنعت، مطابق سند نیازمندی‌های محصول (`PRD_Document.txt`).
**کارکرد کاملاً آفلاین در شبکه داخلی** — بدون احراز هویت (یک کارشناس محلی)، بدون هیچ درخواست خارجی، داده‌ها روی دیسک محلی سرور.

> قواعد بنیادین محصول:
> - هر پروژه = **یک خط تولید + یک محصول**
> - داده خام هرگز بدون تصمیم کاربر تغییر نمی‌کند؛ رکورد مشکوک فقط «علامت‌گذاری» می‌شود
> - حذف دائمی است اما با **نشانگر حذف (Deletion Marker)** تا هنگام Restore بازنگردد
> - محاسبات با snapshot تنظیمات ثبت می‌شود تا تغییر تنظیمات، نتیجه تاریخی را بی‌صدا عوض نکند

## نسخهٔ آفلاین (Standalone) — تست روی سیستم شخصی

علاوه بر نسخهٔ وب (سرور Next.js)، این مخزن شامل **نسخهٔ آفلاین کامل و هم‌ارز** است که بدون هیچ سرور، نصب یا اینترنت اجرا می‌شود — فقط با باز کردن یک فایل HTML در مرورگر.

### روش استفاده
1. مخزن را دانلود کنید (سبد اختیاری Code → Download ZIP یا `git clone`) و از حالت فشرده خارج کنید.
2. فایل **`Timing2-Offline.html`** (در ریشهٔ مخزن، کنار پوشهٔ `offline/`) را در مرورگر باز کنید (Chrome/Edge/Firefox).
3. برای شروع سریع، دکمهٔ **«بارگذاری داده دمو»** را در صفحهٔ خانه بزنید — پروژهٔ نمایشی کامل (ساختار، وستینگهاوس، ۴ جلسهٔ زمان‌سنجی، دادهٔ مشکوک) ساخته می‌شود.
4. همهٔ ۱۲ بخش (خانه + ۱۱ مرحلهٔ مطالعه) دقیقاً مانند نسخهٔ وب کار می‌کنند: فرمول‌ها، وستینگهاوس، برگهٔ زمان‌سنجی با Paste از Excel، تحلیل OT→NT→ST، نمودار OPC/FPC با درگ، داشبورد، گزارش A4/چاپ، خروجی Excel و پشتیبان‌گیری.

### ذخیره‌سازی و انتقال داده
- داده‌ها در **localStorage همان مرورگر** ذخیره می‌شوند (روی آدرس‌های file:// پشتیبانی می‌شود) و پس از بستن/بازکردن مرورگر باقی می‌مانند.
- برای انتقال به سیستم/مرورگر دیگر: از «داده و پشتیبان» نسخهٔ پشتیبان فایل دانلود کنید یا **بستهٔ کامل پروژه** بگیرید — بسته با نسخهٔ وب هم سازگار است (manifest + checksum SHA-256).
- پشتیبان‌گیری خودکار در حافظهٔ مرورگر + سیاست نگهداشت قابل تنظیم.
- **توجه:** پاک‌کردن دادهٔ سایت/مرورگر، localStorage را نیز پاک می‌کند؛ فایل پشتیبان، پشتیبان مطمئن بلندمدت است.

### تضمین‌های مهندسی
- **بدون هیچ درخواست خارجی**: فونت Vazirmatn به‌صورت base64 تعبیه شده، آیکون‌ها SVG inline، چارت‌ها دست‌ساز — ممیزی شبکه صفر درخواست خارجی.
- **موتور محاسبات**: پورت بایت‌به‌بایت همان `src/calculation` وب (R، NT، ST دو روش، زنجیرهٔ پیوسته، هم‌پوشانی، MAD/IQR، آمار t-CI، تجمیع دو روش) — ۸۰/۸۰ تست خودکار پاس.
- داده خام هرگز حذف نمی‌شود؛ نشانگر حذف، بازیابی ناخواسته را مسدود می‌کند؛ مقادیر همیشه با دقت کامل ذخیره و فقط نمایش گرد می‌شوند.

### ساختار پوشهٔ آفلاین
```
Timing2-Offline.html          ← فایل اجرایی (بیرون از پوشه)
offline/
  VERSION / CHANGELOG.md      ← نسخهٔ آفلاین (قانون همگام‌سازی)
  css/fonts.css               ← فونت تعبیه‌شده (base64)
  css/app.css                 ← توکن‌های طراحی (عین نسخهٔ وب)
  js/utils.js                 ← ارقام فارسی، تقویم جلالی، قالب‌بندی
  js/formulas.js              ← پورت دقیق موتور محاسبات
  js/db.js                    ← لایهٔ داده + تمام سرویس‌ها (localStorage)
  js/ui.js                    ← کیت UI (دیالوگ/توست/چارت‌های SVG)
  js/app.js                   ← روتر و شل
  js/views-*.js               ← ۱۲ نمای برنامه
```

### 🔁 پروتکل همگام‌سازی (الزامی در هر تغییر آینده)
هر تغییر در نسخهٔ وب باید **در همان جلسه** به نسخهٔ آفلاین هم منتقل شود:
1. تغییر منطق محاسبات/سرویس → همزمان در `offline/js/formulas.js` یا `offline/js/db.js`
2. تغییر برچسب/متن UI → فایل نمای متناظر (`views-*.js`)
3. پس از هر همگام‌سازی: افزایش `offline/VERSION` + ثبت در `offline/CHANGELOG.md`
4. اجرای `bun scripts/test-offline-core.js` (باید ۸۰/۸۰ پاس بماند) + تست مرورگر `file://`
نگاشت ماژول‌ها: `src/calculation/*` ↔ `formulas.js`، `src/application/*` ↔ `db.js`، `src/views/**` ↔ `views-*.js`، `src/lib/{persian,jalali,format}.ts` ↔ `utils.js`، `src/app/globals.css` ↔ `app.css`.

## راه‌اندازی

پیش‌نیاز: [Bun](https://bun.sh) (نسخه ۱.۱ یا بالاتر)

```bash
# ۱) نصب وابستگی‌ها
bun install

# ۲) تنظیمات محیط (مسیر پایگاه داده SQLite)
cp .env.example .env

# ۳) ایجاد پایگاه داده از اسکیما
bun run db:push

# ۴) اجرای محیط توسعه روی پورت 3000
bun run dev
```

اجرای تولید (سرور شبکه داخلی):

```bash
bun run build
bun run start
```

برنامه **تک‌مسیره** است (`/`) و ناوبری داخلی با hash انجام می‌شود؛ همه APIها زیر `/api/` قرار دارند.

### آزمون‌های الزامی PRD

```bash

bun scripts/verify-phase7.ts     # فاز ۷ — ۷۲ سنجه (FR-24/25/26 + آفلاین)
```

فاز ۱ و ۲ (۱۰۲ سنجه): ۵ فرمول اجباری وستینگهاوس/مجازها/روش پیوسته/فواصل هم‌پوشان، آمار، MAD، ارقام فارسی و تقویم جلالی،
جریان کامل API (ساختار، ارث‌بری مجازها، ارزیابی، Idempotency، کنترل هم‌زمانی، کپی، بسته، حذف دائمی، Restore با نشانگرها،
وضعیت مراحل، نهایی‌سازی) — خروجی نهایی باید «همه آزمون‌ها موفق بودند» باشد.

فاز ۳ (۸۳ سنجه): آزمون‌های مرجع **B6** (قرائت‌های ۸، ۲۰، ۴۵ → مدت‌های ۸، ۱۲، ۲۵) و **B7**
(بازه‌های [۰،۸]+[5،25] → مجموع ۲۸، سپری‌شده ۲۵) از طریق API واقعی + زنجیرهٔ پیوسته بین چرخه‌ها،
ردّ قرائت نزولی/زمان منفی/بازهٔ نامعتبر، Paste با پیش‌نمایش و دو حالت ثبت، خروج از محاسبه بدون حذف خام،
بازگردانی چرخهٔ حذف‌شده (Undo)، تغییرناپذیری روش جلسه، جلسهٔ بستهٔ فقط‌خواندنی، جلسهٔ جدید مستقل،
وضعیت مرحلهٔ زمان‌سنجی و ارقام فارسی.

فاز ۴ (۶۸ سنجه): آزمون‌های مرجع **B1** (OT=۸٫۳۰ × R=۱٫۰۹ → NT=۹٫۰۴۷)، **B2** (NT=۹٫۰۴۷، A=۰٫۱۵ →
روش ۱: ۱۰٫۴۰۴۰۵ / روش ۲: ≈۱۰٫۶۴۳۵۲۹)، **B5** (خروج از محاسبه: خام حفظ + خارج از میانگین) و

(SD/واریانس/CV/چارک/IQR/CI-t؛ n<۲ → null نه صفر)، علامت‌گذاری مشکوک با MAD و امتیاز ثبت‌شده،

فعالیت هم‌پوشان (NEEDS_AGGREGATION_RULE، سپری‌شده=۲۵ نه ۲۸)، پیشرفت نمونه و Snapshot سه‌نسخه‌ای.

فاز ۶ (۹۹ سنجه): کارت‌های خلاصهٔ داشبورد با مقادیر مرجع (ST = جمع عناصر با R=۱٫۰۹ و A=۸٪ — شامل
مشاهدهٔ مشکوک طبق FR-11)، علت به‌جای صفر در پروژهٔ خالی، شخصی‌سازی چیدمان (ذخیره/بازیابی/بدون STALE‌کردن
محاسبات)، گزارش کامل مطالعه (فرمول ST، روش کرنومتر جلسات، تعداد نمونه، خارج‌شده‌ها با دلیل، وستینگهاوس
با درجه‌ها، دسته‌های مجاز مؤثر، پرچم‌های بازبینی و سلب مسئولیت)، گزارش تک‌اپراتوره (آمار همان اپراتور،
جلسه‌های همان اپراتور، null به‌جای صفر برای مفاهیم سطح کل فعالیت)، اعتبارسنجی فایل Excel با خواندن
مجدد (امضای PK، شیت RTL، مقادیر عددی واقعی، فیلتر اپراتور)، نوع نامعتبر (۴۲۲) و وضعیت چهارگانهٔ
مراحل جدید + رفع آن با خروج مشکوک از محاسبات.

فاز ۷ (۷۲ سنجه): پشتیبان دستی/خودکار/حفاظتی با manifest و checksum و اعتبارسنجی نسخهٔ ساختار؛
بازیابی با تأیید صریح (بدون تأیید → 422)، بازگشت واقعی داده (پروژهٔ زائد حذف شد، پروژهٔ اصلی باقی ماند)،
بازیابی از فایل آپلودی؛ فایل خراب → `BACKUP_CHECKSUM_MISMATCH` (نه بازیابی خاموش)؛ زمان‌بندی خودکار
(خاموش → skip، سررسیده → 201، زودهنگام → `NOT_DUE_YET`) و چرخش نگهداری (۴ نسخهٔ AUTO → ۳)؛
بستهٔ خروجی با manifest/checksum/ارزیابی‌های وستینگهاوس/مشاهدات خام؛ ورود همیشه پروژهٔ جدید
(پسوند «(ورودی)»، remap کامل شناسه‌ها، ST یکسان = ۶٫۵۰۴۰۳)؛ بستهٔ خراب/JSON نامعتبر/نسخهٔ جدیدتر →
خطاهای ساختاریافته؛ حذف دائمی ایستگاه (شمار وابستگی، حذف واقعی از DB، رویداد حداقلی بدون کپی محتوا)؛
**نشانگر حذف: دادهٔ حذف‌شدهٔ دائمی با Restore برنمی‌گردد (آزمون اجباری #۸)**؛
**آفلاین: HTML بدون هیچ منبع خارجی (آزمون اجباری #۱۰)** و رگرسیون فرمول‌ها پس از Restore
(ST = NT × 1.08 همچنان دقیق).

## راهنمای راهبری — نصب، پشتیبان‌گیری، بازیابی و رفع اشکال (فاز ۷)

### نصب روی سرور/کامپیوتر داخلی

1. پیش‌نیاز: Bun ≥ ۱٫۱ روی سیستم عامل میزبان (ویندوز/لینوکس) — بدون نیاز به اینترنت پس از نصب بسته‌ها.
2. کپی پوشهٔ پروژه، سپس: `bun install` (یک‌بار، با اینترنت یا از کش محلی)، `bun run db:push`، `bun run dev`
   (یا برای بهره‌برداری دائم: `bun run build && bun run start`).
3. مرورگرهای شبکه داخلی فقط به `http://<آدرس-سرور>:3000` وصل می‌شوند؛ هیچ درخواست خارجی رد و بدل نمی‌شود
   (آزمون‌شده — verify-phase7 بخش O1).
4. مسیر داده‌ها: `app-data/` شامل `database/` (فایل SQLite) و `backups/` (نسخه‌های پشتیبان JSON).
   **فایل پایگاه داده را روی درایو/پوشهٔ شبکه‌ای قرار ندهید** (مطابق قید ۶.۷ سند).

### پشتیبان‌گیری

- **خودکار**: تنظیمات در «داده و پشتیبان ← پشتیبان‌گیری خودکار» — فعال/غیرفعال، فاصلهٔ ۵ تا ۲۴۰ دقیقه،
  نگهداری ۳ تا ۵۰ نسخه. نسخه‌های خودکار قدیمی‌تر از سقف نگهداری در اولین پشتیبان‌گیری بعدی حذف می‌شوند (چرخش).
- **دستی**: دکمهٔ «ایجاد پشتیبان دستی» — همیشه در همان سرور ذخیره می‌شود و قابل دانلود است.
- **محتوای پشتیبان**: تمام داده‌های همهٔ پروژه‌ها + تنظیمات سراسری + تاریخچهٔ Audit، با manifest شامل
  نسخهٔ ساختار و checksum (تشخیص خرابی).
- **سیاست**: پشتیبان روی همان دیسکِ پایگاه داده، تنها نسخهٔ پشتیبان محسوب نمی‌شود؛ فایل‌های دانلودشده را
  روی فضای ذخیره‌سازی داخلی دیگری نگه دارید.

### بازیابی (Restore)

1. در فهرست نسخه‌ها روی «بازیابی» کلیک کنید — گفت‌وگوی تأیید، تاریخ/حجم/نسخهٔ ساختار/تعداد پروژه و
   **اثر جایگزینی کامل داده‌ها** را نشان می‌دهد.
2. پیش از جایگزینی، یک **پشتیبان حفاظتی** خودکار گرفته می‌شود (در فهرست با برچسب «حفاظتی»).
3. پس از بازیابی، checksum و نسخهٔ ساختار اعتبارسنجی و **نشانگرهای حذف دائمی** اعمال می‌شوند:
   داده‌هایی که قبلاً با تأیید حذف شده‌اند، از نسخهٔ پشتیبان **بازنمی‌گردند** (FR-26).
4. بازیابی از فایل: دکمهٔ «بازیابی از فایل» — همان اعتبارسنجی‌ها؛ فایل خراب با پیام مشخص رد می‌شود.
5. اگر نسخهٔ ساختار فایل از نرم‌افزار فعلی جدیدتر باشد، ابتدا نرم‌افزار را به‌روز کنید.

### بستهٔ کامل پروژه (انتقال بین نصب‌ها)

- **خروجی**: «داده و پشتیبان ← بستهٔ پروژه ← خروجی بستهٔ کامل» — فایل JSON با manifest، checksum،
  ساختار، تنظیمات، گروه‌های مجاز، داده‌های خام، ارزیابی‌های وستینگهاوس و نمودارها.
- **ورود**: از صفحهٔ خانه، دکمهٔ «ورود بسته» — همیشه **پروژهٔ جدید** می‌سازد (پروژهٔ موجود بازنویسی نمی‌شود)،
  تمام شناسه‌ها بازتولید می‌شوند و پیش از ورود، ساختار/نسخه/checksum اعتبارسنجی می‌شود.

### حذف دائمی

- حذف ایستگاه/فعالیت/عنصر/پروژه فقط پس از نمایش شمارش وابستگی‌ها و تأیید صریح انجام می‌شود؛
  در یک تراکنش اتمیک اجرا می‌شود و رویداد حداقلی (نوع + شناسه، بدون محتوای حذف‌شده) در تاریخچه ثبت می‌شود.
- سطل بازیافت وجود ندارد (تصمیم مالک محصول). تنها راه بازگشت، Restore نسخهٔ پشتیبانِ پیش از حذف است —
  که نشانگرهای حذف در آن نیز اعمال می‌شوند و دادهٔ حذف‌شده عمداً برنمی‌گردد.

### رفع اشکال

| نشانه | علت احتمالی | اقدام |
|---|---|---|
| «فایل پشتیبان روی دیسک یافت نشد» | فایل از پوشهٔ `app-data/backups` جابه‌جا/حذف شده | فایل را برگردانید یا نسخهٔ دیگری بازیابی کنید |
| «checksum مطابقت ندارد» | فایل پشتیبان آسیب دیده | از نسخهٔ دیگری استفاده کنید |
| «نسخه ساختار جدیدتر است» | فایل از نسخهٔ جدیدتر نرم‌افزار | نرم‌افزار را به‌روز کنید |
| دادهٔ حذف‌شده پس از Restore برنگشت | رفتار خواسته‌شده (نشانگر حذف) | برای بازگشت کامل، حذف را از «فهرست نشانگرها» در نسخهٔ بسیار قدیمی‌تر جست‌وجو نکنید — به‌جای آن پیش از حذف، بستهٔ پروژه خروجی بگیرید |
| خطای هم‌زمانی (409) در ذخیره | رکورد در جای دیگری تغییر کرده | صفحه را تازه‌سازی کنید و دوباره ذخیره کنید |
| درخواست خارجی در لاگ مرورگر | — | نباید رخ دهد؛ اگر دیدید گزارش کنید (قید آفلاین نقض شده است) |

## معماری (پنج لایه)

```
src/
├── app/            # مسیرها + Route Handlers (API REST با Zod و خطاهای فارسی ساخت‌یافته)
├── application/    # سرویس‌های کاربردی (پروژه، ساختار، مجازها، ارزیابی، زمان‌سنجی، تحلیل، Snapshot محاسبات، داشبورد، گزارش، تنظیمات)
├── domain/         # انواع دامنه + اعتبارسنجی ورودی + برچسب‌ها
├── calculation/    # موتور محاسبات خالص (فرمول‌های اجباری — بدون وابستگی به فریم‌ورک)
├── infrastructure/ # پشتیبان/Restore، تاریخچه، نشانگر حذف، سریال‌سازی بسته، خروجی Excel، داده Seed
├── views/          # نماها (SPA — Home و مراحل پروژه)
├── components/     # اجزای مشترک و چیدمان (شل، سایدبار مراحل، فوتر چسبان)
├── store/          # Zustand (ناوبری/نمایش)
└── lib/            # کلاینت API، قالب‌بندی، تقویم جلالی، ارقام فارسی
prisma/schema.prisma # مدل داده (UUID، Cascade صریح، فیلدهای snapshot)
```

### نکات کلیدی پیاده‌سازی

- **موتور محاسبات** (`src/calculation/`): `R = 1 + S + E + C + Cons`، `NT = OT × R`،
  `ST = NT × (1+A)` و `ST = NT / (1−A)` (با قید A < 1)، مشتق مدت‌ها از قرائت پیوسته،
  مجموع فواصل و زمان سپری‌شده چرخه هم‌پوشان، آمار توصیفی (SD/CV)، تشخیص غیرعادی MAD (فقط علامت‌گذاری).
- **Westinghouse**: جدول Seed با هشدار «نسخه رایج — نیازمند تأیید کارشناس»، ویرایش با
  «ذخیره به‌عنوان نسخه جدید» (محاسبات تاریخی به نسخه قبلی ارجاع می‌مانند)، ارزیابی هر عنصر یک‌بار
  و کپی از عنصر مشابه.
- **پشتیبان‌گیری**: خودکار زمان‌بندی‌شده با چرخش نسخه‌ها، دستی، حفاظتی پیش از Restore؛
  اعتبارسنجی checksum و نسخه ساختار؛ اعمال نشانگرهای حذف پس از Restore.
- **کنترل هم‌زمانی و Idempotency**: `expectedUpdatedAt` (409 در تعارض) و `x-change-id` (پاسخ کش‌شده).
- **آفلاین**: فونت Vazirmatn به‌صورت محلی بسته‌بندی شده (مجوز SIL OFL 1.1)،
  بدون CDN و بدون درخواست خارجی؛ تله‌متری Next.js غیرفعال (`.env`).
- **رابط کاربری**: فارسی RTL، تقویم شمسی و ارقام فارسی (قابل تغییر به میلادی/لاتین)،
  تم روشن/تیره، واکنش‌گرا (موبایل: جدول‌ها به کارت تبدیل می‌شوند)، راهنمای آیکونی هر فیلد با مثال.
- **خروجی PDF (رویکرد آفلاین)**: چون کتابخانه‌های سرور-side PDF متن فارسی را بدون شکل‌دهی HarfBuzz
  خراب می‌کنند، خروجی PDF از **چاپ بومی مرورگر** گرفته می‌شود (دکمهٔ «چاپ / ذخیره PDF» + CSS چاپ A4).
  متن کاملاً متصل و RTL، بدون هیچ وابستگی خارجی زمان اجرا — مطابق قید ۶.۹ سند. اعداد Excel به‌صورت
  «عدد واقعی» نوشته می‌شوند تا تحلیل داده ممکن باشد؛ ارقام فارسی در متن‌ها و تاریخ‌ها (مطابق تنظیمات).

### اصلاحات یافته‌شده در آزمون‌های فاز ۷ (شفافیت کامل)

1. **نشانگر حذف ریشهٔ ایستگاه/فعالیت**: درخت وابستگی فقط فرزندان را نشانه‌گذاری می‌کرد؛ پس از Restore
   ایستگاهِ حذف‌شده به‌صورت «شبح خالی» برمی‌گشت. رفع: `collectStationsTreeIds`/`collectActivitiesTreeIds`
   اکنون شناسهٔ خودِ ریشه را نیز شامل می‌شوند — آزمون D2 پاس شد.
2. **ارزیابی‌های وستینگهاوس در بستهٔ خروجی**: بخش‌های بسته `ratingAssessment` را پوشش نمی‌دادند (نقض FR-25).
   رفع: به بخش «جدول‌های وستینگهاوس» افزوده شد و ورود بسته آن را با remap منتقل می‌کند — آزمون P1/P2 پاس شد.
3. **سرریز متن checksum در موبایل**: مقدار هگز بلند در جزئیات تاریخچه بدون شکستن خط نمایش داده می‌شد.
   رفع: `break-all` روی مقادیر قبل/بعد — تأیید با اسکرین‌شات ۳۹۰px و اندازه‌گیری DOM.

### محدودیت‌ها و موارد باقیماندهٔ شناخته‌شده

- **فایل‌های پیوست**: مدل داده آماده است اما در نسخهٔ اول آپلود پیوست فعال نیست (PRD: «در صورت وجود») —
  بستهٔ پروژه نیز پیوست ندارد.
- **کفایت آماری**: رسیدن به هدف نمونه به‌عنوان اثبات کفایت معرفی نمی‌شود (تصمیم صریح PRD)؛
  آزمون کفایت رسمی (مثلاً بر مبنای CV) به تصمیم کارشناسی آتی واگذار شده و صادقانه اعلام می‌شود.
- **چیدمان دستی نمودار در بازیابی**: مختصات گره‌ها در پشتیبان/بسته منتقل می‌شود، اما Restore سراسری
  چیدمان پروژه‌های دیگر را نیز از همان نسخه می‌آورد — طبیعت Restore کامل است و محدودیت نیست.
- **تقویم/ارقام**: دادهٔ تاریخ به‌صورت ISO نگهداری و تبدیل شمسی/میلادی فقط در نمایش انجام می‌شود (FR-29).
