# ADR-006: راهبرد آفلاین — PWA + IndexedDB + صف همگام‌سازی idempotent

**وضعیت:** پذیرفته‌شده — **تاریخ:** ۲۹ اکتبر ۲۰۲۶ — **فاز:** صفر (طراحی) / ۳-۴ (پیاده‌سازی)

## زمینه
B12: کار در کارخانه با اینترنت ناپایدار؛ عملیات ضروری آفلاین تعریف شود؛ صف/شناسه یکتا/جلوگیری از تکرار/حل تعارض؛ بدون ادعای همگام‌سازی موفق جعلی.

مرجع فنی: MDN «Offline and background operation» (بازیابی ۲۰۲۶-۱۰-۲۹) + Microsoft Edge PWA/IndexedDB راهنما.

## تصمیم
۱. **Service Worker** برای precache دارایی‌ها + استراتژی شبکه-اول با عقب‌گرد به کش برای API داده.
۲. **IndexedDB** به‌عنوان بافر محلی ساخت‌یافته (صف عملیات، جلسه فعال، کش پروژه فعال).
۳. **کلید idempotent (`clientOpId` UUIDv7)** روی هر عملیات آفلاین → retry/کلیک تکراری دوباره‌شماری نمی‌کند.
۴. ترتیب flush عمدی: رویداد زمان‌سنجی → مقادیر → سایر.
۵. خط‌مشی تعارض:
   - رویدادها append-only → تعارض بازنویسی ندارند؛ dedup با کلید.
   - مقادیر/سناریوها: نسخه + `updatedAt` → در تعارض، وضعیت `conflict` و **تصمیم صریح کاربر** (دو مقدار نمایش داده می‌شود).
   - ConfigVersion فقط آنلاین ایجاد می‌شود.
۶. UI وضعیت واقعی: `آفلاین | در صف | همگام | تعارض | بازیابی‌شده`.

## گزینه‌های رد‌شده
- LocalStorage برای داده ساخت‌یافته: حجم/تراکنش/ایندکس ناکافی.
- CRDT کامل (Yjs/Automerge): پیچیدگی ادغام در داده‌ای که ذاتاً append-only یا نسخه‌دار است — ارزش افزوده کم.
- اتصال دائم به سرور به‌عنوان پیش‌نیاز: نقض B12.

## پیامدها
✅ ثبت مطمئن در قطعی؛ هیچ ادعای همگام بدون تأیید.
⚠️ تست آفلاین واقعی (قطع شبکه در آزمون فاز ۳/۴) الزامی؛ پشتیبانی Background Sync وابسته به مرورگر است.
