# ADR-009: کنترل دسترسی — RBAC پروژه‌محور با مجوزسنجی سرور در هر API

**وضعیت:** پذیرفته‌شده — **تاریخ:** ۲۹ اکتبر ۲۰۲۶ — **فاز:** صفر

## زمینه
A5: هر عملیات خواندن/ویرایش/حذف/خروجی در سمت سرور مجوزسنجی می‌شود؛ مخفی‌کردن در UI کافی نیست. B10: کاربر مجاز تخصیص بالانس را دستی تغییر دهد. مرجع: OWASP Multi-Tenant Security Cheat Sheet (بازیابی ۲۰۲۶-۱۰-۲۹).

## تصمیم
۱. **RBAC در سطح پروژه** با نقش‌های قابل توسعه: `owner / editor / recorder / viewer / admin`.
۲. احراز هویت: **NextAuth v4** (Credentials برای نسخه پایه؛ آماده افزودن OAuth سازمانی).
۳. **هر API Route** به‌ترتیب: session → نقش در projectId → فیلتر کوئری با projectId. پاسخ خطا بدون افشای وجود/عدم وجود رکورد (404 عمومی برای بی‌مجاز).
۴. AuditLog عملیات حساس: حذف منطقی، اصلاح مشاهده، تغییر ConfigVersion، کپی پروژه، تغییر نقش‌ها.
۵. شناسه‌های خارجی UUID (نه ترتیبی) → حدس‌زدن id دیگر پروژه‌ها بی‌ارزش است.

## گزینه‌های رد‌شده
- **ABAC کامل:** پیچیدگی سیاست‌ها بیش از نیاز فعلی؛ RBAC + قواعد چند موردی کافی است.
- **اتکا به فیلتر UI:** نقض صریح A5.

## پیامدها
✅ جداسازی پروژه‌ها در سرور؛ قابل آزمون با درخواست مستقیم API (شرط پذیرش فاز ۱).
⚠️ نگهداری جدول نقش-مجوز در `shared/contracts/acl.ts` به‌عنوان تنها مرجع (UI و سرور از یک تعریف می‌خوانند).
