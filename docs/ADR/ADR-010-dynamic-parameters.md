# ADR-010: ذخیره پارامترهای پویا — جداسازی تعریف/مقدار + JSON ساخت‌یافته

**وضعیت:** پذیرفته‌شده — **تاریخ:** ۲۹ اکتبر ۲۰۲۶ — **فاز:** صفر

## زمینه
B2: انواع داده گسترده، ویژگی‌های سفارشی «بدون افزودن ستون فیزیکی برای هر پارامتر»؛ تعریف از مقدار جداست؛ تغییر تعریف بدون تبدیل پنهانی.

## تصمیم
۱. **ParameterDefinition** (تعریف، نسخه‌دار، با `stableKey` و `customAttrsJson`) و **ParameterValue** (مقدار، `valueJson` ساخت‌یافته شامل واحد) دو موجودیت جدا.
۲. `valueJson` به‌ازای نوع داده قالب قطعی دارد (`{v: number, unit: 's'} | {v: string} | …`) — اعتبارسنجی با zod.
۳. فهرست‌های انتخابی با `options` روی تعریف؛ بدون جدول‌های جانبی تا نیاز واقعی.
۴. نقش تحلیلی (`analysisRole`) روی تعریف؛ فرم‌ساز/گزارش از همان تعریف رندر می‌کنند.

## گزینه‌های رد‌شده
- **ستون فیزیکی برای هر پارامتر (Pivot):** مهاجرت schema برای هر تغییر کاربر — غیرعملی.
- **EAV کاملاً آزاد (entity-attribute-value بدون نوع):** از دست رفتن اعتبارسنجی نوع/واحد و کوئری‌های سنگین.
- **ستون JSON واحد روی رکورد اصلی (بدون جداسازی تعریف/مقدار):** نسخه‌بندی تعریف و ردیابی نتایج به نسخه تعریف غیرممکن می‌شود (نقض A7).

## پیامدها
✅ تعریف پارامتر جدید = صرفاً رکورد + JSON (بدون مهاجرت DB)؛ مسیر «پارامتر سفارشی بدون تغییر کد» فاز ۲ برقرار.
⚠️ اعتبارسنجی نوع در لایه Application (zod) حیاتی است؛ کوئری‌های گروه‌بندی روی valueJson ایندکس‌گذاری JSON SQLite را فعال می‌کنند (بازبینی کارایی در فاز ۵).
