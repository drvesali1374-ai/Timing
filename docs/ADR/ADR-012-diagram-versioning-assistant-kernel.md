# ADR-012: نسخه‌بندی نمودار append-only و هسته مشترک دستیار آفلاین

**وضعیت:** پذیرفته‌شده — **تاریخ:** ۳۱ اکتبر ۲۰۲۶ — **فاز:** ۳

## زمینه

فاز ۳ دو تصمیم معماری مهم داشت:

۱. **نسخه‌بندی نمودارهای OPC/FPC** — قید ENGINE_CONTRACTS §۲-۵: «ویرایش هرگز وضعیت تأییدشده را بی‌اجازه بازنویسی نمی‌کند». نمودار داده پروژه است (نه پیکربندی append-only سراسری) اما نیاز به تاریخچه/بازیابی دارد.

۲. **مکان کد دستیار آفلاین** — دستیار باید سمت کاربر (آفلاین) و به‌طور بالقوه سرور کار کند؛ قاعده مرزها «UI فقط shared/lib» بود.

## تصمیم

### الف) نمودار: `Diagram` + `DiagramRevision` (append-only)

- هر سند نمودار = یک ردیف `Diagram` (kind/variant/subject/status/currentRev) + زنجیره `DiagramRevision` (docJson/layoutJson/validationJson/origin/clientOpId).
- **هر ذخیره = revision جدید**؛ نسخه‌ها هرگز ویرایش/حذف نمی‌شوند؛ «بازیابی نسخه» = revision جدید با محتوای قدیم.
- **variant (current/proposed)** با `variantOfId` — نسخه پیشنهادی به نمودار «روش موجود» ارجاع می‌دهد؛ مقایسه = دیف خلاصه‌های دو سند.
- ذخیره روی `confirmed` → status به `draft` برمی‌گردد (تأیید مجدد لازم است) — «بازنویسی بی‌اجازه» از نظر ساختاری ناممکن.
- ذخیره آفلاین با `clientOpId` idempotent روی revision — retry دوباره‌شماری نمی‌کند (ADR-006).

**گزینه‌های رد‌شده:** snapshot در ConfigVersion (نمودار داده پروژه است نه پیکربندی؛ ذخیره مکرر خودکار snapshot پرحجم می‌سازد) · بازنویسی in-place (نقض append-only و بازیابی).

### ب) دستیار: هسته مشترک خالص `src/shared/assistant/` (تعمیم ADR-011)

همان الگوی موتور فرمول: موتور دستیار (پارسر/قواعد/کتابخانه دانش) خالص است و هم UI و هم (آینده) سرور لازم دارد → به‌عنوان **هسته مشترک** در `src/shared/assistant/` نشست، نه ماژول سرورمحور:

- `parser.ts` — متن → پیش‌نویس گام (واژه‌گانه قطعی)
- `rules.ts` — موتور پیشنهاد (قواعد/فرضیه‌ها) با شناسه و نسخه
- `knowledge.ts` — کتابخانه دانش نسخه‌دار (داده خالص در بسته = آفلاین واقعی)
- تشخیص قابلیت WebGPU → `src/lib/local-model.ts` (lib کلاینت)
- صف ذخیره آفلاین IndexedDB → `src/lib/diagram-local-store.ts` (lib کلاینت)

`src/modules/assistant/` حذف شد — قاعده «UI فقط shared/lib» بدون استثنا برقرار ماند (`check:boundaries` ✓).

### پ) اکشن‌های ACL اختصاصی

`diagrams:read` / `diagrams:write` به `PROJECT_ACTIONS` اضافه شد (جدا از `config:write`)؛ owner/editor نوشتن، recorder/viewer فقط خواندن.

## پیامدها

✅ تاریخچه کامل با بازیابی · تأییدشده هرگز بی‌اجازه بازنویسی نمی‌شود · idempotency آفلاین روی revision
✅ مرزهای ماژول سالم (۰ نقض)؛ منطق دامنه در UI ممنوع ماند
⚠️ ذخیره خودکار هر ۳ ثانیه revision می‌سازد — تاریخچه پرتر می‌شود (تصمیم UX: امنیت داده > تراکم؛ قابل تنظیم در فازهای بعد)
