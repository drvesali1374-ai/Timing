# ADR-016: تحویل PWA/Service Worker فاز ۷ + سخت‌سازی هم‌زمانی درج رویداد

**وضعیت:** پذیرفته‌شده — **تاریخ:** ۱ نوامبر ۲۰۲۶ — **فاز:** ۷

## زمینه
ADR-006 (فاز صفر) Service Worker را به فاز ۷ موکول کرده بود: precache پوسته + شبکه-اول برای API با عقب‌گرد. همچنین آزمون‌های فاز ۷ با دو کلاینت هم‌زمان روی یک جلسه، خطای ۵۰۰ واقعی در `ingestEvents` کشف کردند (پنجره رقابت TOCTOU در check-then-insert).

## تصمیم

### ۱) Service Worker (`public/sw.js`)
- **ناوبری:** شبکه-اول → عقب‌گرد به کش `/` → `offline.html` (صفحه فارسی RTL با راهنمای صادقانه).
- **دارایی استاتیک** (`/_next/static/`, آیکون‌ها، فونت‌ها): کش-اول + بازآوری در پس‌زمینه (SWR) با کش نسخه‌دار `tazmin-pwa-v1.0.0-static`.
- **API (`/api/**`): فقط-شبکه** — هرگز پاسخ API کش نمی‌شود؛ صف‌های آفلاین داده ساخت‌یافته (IndexedDB `timing-chrono`/`timing-diagrams` از فاز ۳/۴) مسئولیت داده را دارند. این جداسازی عمدی است: «آفلاینِ پوسته» ≠ «آفلاینِ داده».
- **API احراز هویت** کاملاً دست‌نخورده.
- **PWA نصب‌پذیر:** `manifest.webmanifest` (فارسی/RTL/عمودی) + آیکون‌های ۶۴/۱۹۲/۵۱۲ + maskable + شورتکات (زمان‌سنجی/نمودار).
- **ثبت:** `PwaRegister` بعد از `load` (غیرمسدودکننده) + اعلان به‌روزرسانی با اقدام «فعال‌سازی» (skipWaiting + reload یک‌باره) + توست‌های صادقانه قطع/وصل اتصال.
- **نسخه‌بندی کش:** با تغییر `APP_VERSION` کش‌های قدیمی در activate حذف می‌شوند.

### ۲) رفع رقابت درج رویداد (`timing-repo.ts`)
الگوی check-then-insert در `insertEventRow` در پنجره رقابت به قید یکتای DB (`P2002`) می‌خورد و ۵۰۰ می‌داد. رفع: catch صریح `P2002` → تفکیک قید `clientEventId` (= duplicate) از `sessionId_seq` (= seq-conflict با بازخوانی مالک). نتیجه آزموده‌شده: دو کلاینت هم‌زمان → ingested=۳+duplicates=۳، شمار سرور دقیق ۳، **هرگز ۵۰۰**.

## گزینه‌های رد‌شده
- **کش پاسخ API در SW:** نقض یکپارچگی داده (مقادیر/نتایج کهنه) و تعارض با صف‌های idempotent موجود.
- **Workbox:** برای ۳ استراتژی ساده، وابستگی+پیش‌بیلد اضافه بدون ارزش افزوده.
- **تراکنش serializable برای درج رویداد:** SQLite file-level locking ریسک قفل طولانی دارد؛ catch قید یکتا + شمارش duplicate همان تضمین را با هزینه کمتر می‌دهد.

## پیامدها
✅ آفلاینِ پوسته در بیلد تولید کار می‌کند (چانک‌های هش‌شده پایدار)؛ در dev فقط تا حد کش ناپایدار چانک‌های Turbopack — مستند شد.
✅ idempotency تحت هم‌زمانی واقعی اثبات شد (آزمون رقابت ۷۵/۷۵).
⚠️ قید ثانویه: در پنجره رقابت روی seq متفاوت، seq جایگزین صریح تخصیص می‌یابد (append-only حفظ می‌شود).
