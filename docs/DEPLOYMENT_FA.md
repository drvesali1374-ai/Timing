# راهنمای نصب، استقرار و نگهداری (فارسی)

**نسخه:** ۱٫۰٫۰ (فاز ۷ — یکپارچه‌سازی و انتشار) · **تاریخ:** ۱ نوامبر ۲۰۲۶
**دامنه:** نصب در محیط توسعه، استقرار تک-سروری، متغیرهای محیطی، پشتیبان‌گیری/بازیابی، مهاجرت نسخه و عیب‌یابی.

## ۱. پیش‌نیازها

| اجزا | نسخه تأییدشده | یادداشت |
|---|---|---|
| Node.js | ≥ ۲۰ (۲۴ آزموده شد) | برای اجرای اسکریپت‌های آزمون |
| Bun | ≥ ۱٫۳ | نصب وابستگی‌ها + اجرای اسکریپت‌های پشتیبان/seed |
| پایگاه داده | SQLite ۳ | فایل محلی — بدون سرویس خارجی |
| مرورگر هدف | Chromium/Edge/Chrome به‌روز | Firefox/Safari پشتیبانی می‌شود به‌جز WebGPU اختیاری دستیار |

پشته فناوری: Next.js 16 (App Router) · React 19 · TypeScript 5 · Tailwind CSS 4 · shadcn/ui · Prisma 6 · NextAuth v4 · Zod 4 · TanStack Query 5 · Zustand 5 · React Flow 12.

## ۲. نصب در محیط توسعه

```bash
# ۱) دریافت سورس
git clone https://github.com/drvesali1374-ai/Timing.git && cd Timing

# ۲) نصب وابستگی‌ها (با bun)
bun install

# ۳) متغیرهای محیطی
cp .env.example .env
# سپس مقدار واقعی بسازید:
#   DATABASE_URL=file:<مسیر-مطلق>/db/custom.db
#   NEXTAUTH_SECRET=$(openssl rand -hex 32)

# ۴) ایجاد اسکیمای پایگاه داده
bun run db:push

# ۵) داده نمونه آموزشی (idempotent)
bun run seed

# ۶) اجرای سرور توسعه
bun run dev        # → http://localhost:3000
```

**ورود نمونه آموزشی:** `demo@timing.local` / `demo1234` (پروژه DEMO-101 با آن ساخته می‌شود).

## ۳. متغیرهای محیطی

| متغیر | الزامی | توضیح |
|---|---|---|
| `DATABASE_URL` | ✅ | آدرس SQLite به‌شکل `file:<مسیر>/custom.db` — مسیر مطلق توصیه می‌شود |
| `NEXTAUTH_SECRET` | ✅ | رمز امضای نشست — با `openssl rand -hex 32` بسازید؛ **هرگز** `change-me` یا مقدار پیش‌فرض را در تولید استفاده نکنید |
| `NEXTAUTH_URL` | در استقرار پشت دامنه | آدرس عمومی مثل `https://timing.example.com` |
| `TEST_BASE_URL` | خیر | هدف آزمون‌های یکپارچگی (پیش‌فرض `http://localhost:3000`) |
| `DATABASE_FILE` | خیر | مسیر فایل DB برای اسکریپت‌های پشتیبان/بازیابی (پیش‌فرض `db/custom.db`) |

**قاعده امنیتی:** فایل `.env` هرگز کامیت نمی‌شود (`.gitignore`: الگوی `.env*` با استثنای `!.env.example`). رازها را فقط از مسیر محیط operative تزریق کنید.

## ۴. استقرار هدف (تک-سروری)

محصول برای استقرار **خود-میزبانی‌شده تک-سایتی** طراحی شده است (ADR-002/005):

### ۴٫۱ با بیلد standalone

```bash
bun run build                       # خروجی .next/standalone
bun run start                       # NODE_ENV=production روی پورت 3000
```

**پیکربندی برعکس (reverse proxy):** سرور را پشت Nginx/Caddy با HTTPS قرار دهید؛
`NEXTAUTH_URL` را برابر آدرس عمومی تنظیم کنید و هدر `X-Forwarded-Proto` را پاس دهید (NextAuth برای ساخت redirectهای درست).

### ۴٫۲ اجرای پایدار

از systemd/supervisor/PM2 برای ری‌استارت خودکار استفاده کنید:

```ini
# نمونه systemd: /etc/systemd/system/timing.service
[Unit]
Description=Industrial Time Study Platform
After=network.target

[Service]
WorkingDirectory=/opt/timing
EnvironmentFile=/opt/timing/.env
ExecStart=/usr/bin/bun /opt/timing/.next/standalone/server.js
Restart=always
User=timing

[Install]
WantedBy=multi-user.target
```

### ۴٫۳ PWA

پس از اولین بازدید مرورگر، Service Worker نصب می‌شود (`/sw.js`):
دارایی‌های استاتیک کش-اول + ناوبری شبکه-اول با عقب‌گرد به کش؛ `/api/*` هرگز کش نمی‌شود (یکپارچگی داده — ADR-016). نصب روی دسکتاپ/موبایل از منوی مرورگر («نصب برنامه») پشتیبانی می‌شود.

## ۵. پشتیبان‌گیری و بازیابی (R7-4 — آزموده‌شده)

```bash
# پشتیبان‌گیری: چک‌پوینت WAL → کپی → integrity_check → شمار موجودیت‌ها → SHA-256
bun run backup:db
# خروجی: db/backups/custom-YYYYMMDD-HHMMSS.db + .meta.json

# بازیابی: صدق‌سنجی پشتیبان → نقطه بازگشت از وضعیت فعلی → جایگزینی → راستی‌آزمایی
bun run restore:db -- db/backups/custom-2026-11-01-10-39-.db
```

**نکات:**
- پس از بازیابی، سرور را **ری‌استارت** کنید تا Prisma فایل تازه را باز کند.
- بازیابی همیشه یک `pre-restore-*` از وضعیت پیش از بازیابی می‌سازد (نقطه بازگشت).
- هش SHA-256 در `.meta.json` برای ردیابی یکپارچگی پشتیبان ثبت می‌شود.
- **زمان‌بندی پیشنهادی:** پشتیبان روزانه + نگهداری ۳۰ نسخه + کپی خارج از سرور.
- چرخه کامل (پشتیبان → تغییر داده → بازیابی → راستی‌آزمایی بازگشت) در فاز ۷ واقعاً اجرا شد — شاهد: `docs/evidence/phase7-tests/backup-restore-R7-4.txt`.

## ۶. مهاجرت نسخه و ارتقا

- **اسکیمای Prisma:** `bun run db:push` (محیط توسعه) یا `bun run db:migrate` (محیط تولید، با تاریخچه مهاجرت). پیش از ارتقا همیشه `bun run backup:db`.
- **نسخه‌های snapshot پیکربندی:** append-only هستند و نیازی به مهاجرت ندارند — v1 هنگام خواندن به v2 ارتقا می‌یابد (ADR-011).
- **ارتقای وابستگی‌ها:** پس از هر ارتقا کل آزمون‌ها را اجرا کنید:
  ```bash
  bun test src/shared        # ۲۱۵ آزمون واحد هسته
  bun run test:phase1..7     # یکپارچگی فازها
  bun run lint && bunx tsc --noEmit
  ```
- **قفل نسخه:** ارتقاهای فاز ۷ (Next 16.4.3 / next-auth 4.24.15 / zod 4.6.7) با رگرسیون کامل ۲۹۶+۷۵ آزمون تأیید شدند.

## ۷. عیب‌یابی

| نشانه | علت محتمل | راه‌حل |
|---|---|---|
| ۴۰۱های پیوسته/JWEDecryptionFailed | `NEXTAUTH_SECRET` تغییر کرده یا گم شده | مقدر پایدار در `.env` + ری‌استارت؛ نشست‌ها با رمز تازه دوباره ساخته می‌شوند |
| صفحه بعد از restore خالی/داده قدیمی | سرور فایل DB قبلی را باز نگه داشته | ری‌استارت سرور پس از بازیابی |
| خطای `P2002` در ثبت رویداد زنجیره‌ای | دو کلاینت هم‌زمان (مدیریت‌شده) | سیستم idempotency خودکار duplicate می‌شمارد؛ نیازی به اقدام نیست (فاز ۷) |
| نمودار SVG در خروجی تصویر خراب | فونت سیستم بیننده | خروجی PNG از مرورگر ثبت‌کننده تولید شود (زنجیره Vazirmatn→Tahoma) |
| SW آفلاین کار نمی‌کند | هنوز بار دوم بازدید نشده | SW دارایی‌ها را از بازدید دوم کش می‌کند؛ در dev چانک‌ها بین rebuild ناپایدارند — با بیلد تولید آزمایش شود |
| خطای «پایگاه داده قفل است» | دو فرآیند روی یک فایل SQLite | فقط یک نمونه سرور روی هر فایل DB |
| تحلیل خالی | جلسات نهایی‌نشده | تحلیل فقط از جلسات `finalized` می‌خواند (طرح عمدی ثبات ورودی) |

## ۸. پورت‌ها و سرویس‌های جانبی

سرور اصلی فقط **پورت ۳۰۰۰**؛ سرویس‌های جانبی (در صورت فعال‌سازی) از پوشه `mini-services/` با پورت اختصاصی و از مسیر `?XTransformPort=` عبور داده می‌شوند.

## ۱۰. محدودیت‌های استقرار شناخته‌شده

- **تک-سرور/تک-فایل SQLite:** هم‌زمانی نوشتن بالا پشتیبانی نمی‌شود؛ مهاجرت به PostgreSQL در ADR-005 مستند است.
- **XLS = SpreadsheetML 2003** (نه xlsx باینری) — در Excel/LibreOffice باز می‌شود با هشدار احتمالی پسوند.
- **PDF از مسیر چاپ مرورگر** تولید می‌شود (بی‌نقصی RTL فارسی) — سمت سرور PDF تولید نمی‌شود.
- فهرست کامل: `docs/KNOWN_LIMITATIONS.md`.
