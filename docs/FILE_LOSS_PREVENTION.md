# جلوگیری از گم‌شدن فایل‌ها — تحلیل ریشه و رویه بازیابی

**تاریخ ثبت:** ۱ نوامبر ۲۰۲۶ — **فاز:** ۶ (درس‌آموخته فاز‌های ۱-۵) — **وضعیت:** فعال

## ۱. ریشه مشکل (چه اتفاقی افتاد؟)

در طول فازهای قبلی **دو مکانیزم مستقل** باعث گم‌شدن فایل‌ها از سرور محلی می‌شد:

### ۱-۱. الگوهای خطرناک `.gitignore` (علت اصلی — سورس‌ها)

الگوی **بدون لنگر** (بدون `/` ابتدایی) در gitignore روی **هر عمقی** از مخزن اعمال می‌شود،
نه فقط ریشه:

| الگوی تاریخی | قربانی واقعی | پیامد |
|---|---|---|
| `test` (لخت — بعداً رفع شد) | `src/app/api/projects/[id]/config/formulas/test/route.ts` (فاز ۲) | فایل هرگز commit نشد؛ در ریست محیط **برای همیشه گم شد** و در فاز ۵ از نو ساخته شد |
| `local-*` (لخت — رفع در فاز ۶) | `src/lib/local-model.ts` فقط با استثنای دستی نجات یافت | هر فایل آینده `src/**/local-*.ts` بی‌صدا ignore و در ریست بعدی گم می‌شد |

### ۱-۲. فایل‌های عمداً ignore شده + ریست محیط sandbox (علت ثانویه — محیط)

سرور محلی بین جلسات ریست می‌شود. هر آنچه در git نیست، از بین می‌رود:

| فایل | چرا در git نیست | پیامد ریست | بازیابی |
|---|---|---|---|
| `.env` (شامل `NEXTAUTH_SECRET`) | راز — نباید commit شود | کوکی‌های نشست قدیمی نامعتبر → خطای `JWEDecryptionFailed` در لاگ | `bun run restore:env` |
| `db/custom.db` (SQLite + داده) | داده باینری — جای آن seed است | دیتابیس خالی | `bun run restore:env` (push + seed) |

## ۲. اصلاحات اعمال‌شده (فاز ۶)

1. **`.gitignore`:** الگوی `local-*` به `/local-*` لنگر شد (فقط ریشه) و استثنای دستی حذف شد.
   قاعده طلایی: **هر الگوی ignore که عمداً فقط ریشه را هدف دارد، باید با `/` شروع شود.**
2. **`scripts/check-untracked.mjs`** — گارد: هیچ فایلی در `src/ prisma/ scripts/ mini-services/ docs/`
   نباید ignored یا از دیسک حذف‌شده باشد. با `bun run check:untracked` — **قبل از هر کامیت نهایی اجرا شود.**
3. **`scripts/restore-env.mjs`** — بازیابی idempotent محیط: `.env` تازه/تکمیلی + `db push` + seed.
   با `bun run restore:env` — **بعد از هر ریست محیط یا کلون تازه.**

## ۳. رویه استاندارد شروع جلسه / پایان جلسه

**شروع جلسه (پس از ریست محیط):**
```bash
git clone https://github.com/drvesali1374-ai/Timing.git my-project   # اگر مخزن محلی نیست
cd my-project && bun install
bun run restore:env        # .env + دیتابیس + seed
bun run dev                # سرور توسعه
```

**پایان جلسه (قبل از اعلام اتمام):**
```bash
bun run check:untracked    # گارد — باید exit 0 بدهد
git add -A && git commit -m "…" && git push   # همه چیز در مخزن
git fetch && git log origin/main -1           # تأیید push واقعی
```

## ۴. قواعد آینده

- افزودن الگوی جدید به `.gitignore` فقط با لنگر `/` (مگر عمد صریح به همه عمق‌ها — مستند شود).
- اسکریپت/سورس جدید همیشه با `git status` بازبینی شود که واقعاً `untracked` ظاهر شود، نه غایب.
- رازها هرگز commit نمی‌شوند؛ بازیابی آن‌ها وظیفه `restore-env.mjs` است (نه مخزن).
