# کاتالوگ فرمول‌ها و زبان عبارتی (FORMULA CATALOG) — نسخه اولیه

**نسخه:** ۱٫۰ (فاز صفر) — **تاریخ:** ۲۹ اکتبر ۲۰۲۶
**قاعده صداقت:** هر فرمول دارای منبع نوع‌بندی‌شده است: `مرجع متدولوژیک` / `ریاضی محض` / `تعریف محصول`. مقدارهای پیش‌فرض ضرایب، «پیشنهاد قابل ویرایش» هستند نه استاندارد جهانی.

---

## ۱. قرارداد عمومی

- شناسه فرمول: `کلاس-شماره` (مثل `TS-011`)؛ هر فرمول `semver` دارد؛ تغییر → نسخه جدید، نه بازنویسی.
- **واحد پایه زمان:** ثانیه (SI) با دقت میلی‌ثانیه در محاسبات؛ تبدیل نمایشی به دقیقه/ساعت صرفاً لایه UI.
- خروجی هر ارزیابی: `{value, unit, status: valid|invalid|incomplete, errors[], trace, formulaVersion, inputRefs}`.
- قطعیت: ورودی یکسان + نسخه یکسان → نتیجه یکسان (توابع خالص، بدون زمان سیستم/تصادف تزریقی‌نشده).

## ۵. زبان عبارتی امن (DSL) — مشخصات v1

### ۵٫۱. اهداف
ارزیابی فرمول‌های تعریف‌شده کاربر در سطوح: مشاهده / عنصر / چرخه / مجموعه چرخه / گروه / پروژه / سناریو؛ بدون اجرای کد دلخواه.

### ۵٫۲. گرامر (EBNF فشرده)

```ebnf
expr        := or_expr ;
or_expr     := and_expr ( "||" and_expr )* ;
and_expr    := cmp_expr ( "&&" cmp_expr )* ;
cmp_expr    := add_expr ( ("=="|"!="|"<"|"<="|">"|">=") add_expr )* ;
add_expr    := mul_expr ( ("+"|"-") mul_expr )* ;
mul_expr    := unary ( ("*"|"/"|"%") unary )* ;
unary       := ("-"|"!")? primary ;
primary     := number | string | ident call? | "(" expr ")" | if_expr ;
if_expr     := "if" "(" expr "," expr "," expr ")" ;
call        := "(" args? ")" ;
args        := expr ( "," expr )* ;
ident       := [a-zA-Z_][a-zA-Z0-9_.]* ;
```

### ۵٫۳. توابع سفارتی مجاز (فهرست بسته)

| دسته | توابع |
|---|---|
| ریاضی | abs, min, max, round(x,d), floor, ceil, sqrt, pow |
| آمار/تجمیع | sum, mean, median, stddev, count, quantile |
| منطق/شرط | if, and, or, not, isMissing, coalesce |
| واحد | toUnit(x, unit) — فقط از UnitRegistry مجاز |
| زمان | duration(x, unit) |

**ممنوع:** حلقه، تخصیص متغیر، فراخوانی arbitrary، دسترسی به شبکه/DOM/زمان سیستم. عمق AST ≤ ۶۴؛ طول عبارت ≤ ۲۰۴۸ نویسه؛ تعداد گره ≤ ۵۱۲.

### ۵٫۴. جداسازی/مجوز نام‌ها
- شناسه‌های نقطه‌دار = پارامترها (`study.shift`) یا نتایج فرمول‌های دیگر (`TS-011.st`).
- هر شناسه به `inputContract` فرمول قید می‌شود؛ ارجاع ناموجود = خطای پیش از اجرا.

### ۵٫۵. تحلیل ایستا (پیش از ذخیره/اجرا)
۱. Parse → AST (بدون eval؛ پارسر بازگشتی-نزولی اختصاصی — ADR-03).
۲. بررسی نوع تقریبی (عدد/رشته/بولی/خلأ) + سازگاری واحد.
۳. ساخت **گراف وابستگی** فرمول‌ها؛ **چرخه → رد**.
۴. تقسیم بر صفر ثابت → هشدار؛ پویا → بررسی زمان اجرا با خطای مهارشده.

### ۵٫۶. وضعیت‌های ارزیابی
`valid` · `invalid` (خطای ساختاری/نوع/واحد/ارجاع) · `incomplete` (ورودی گمشده مانند ضریب تعیین‌نشده — محاسبه ممکن ولی خروجی وابسته «تأییدنشده» برچسب می‌خورد).

### ۵٫۷. Trace
هر ارزیابی درخت گام‌ها را با (شناسه گره، عمل، مقدار میانی، واحد) در `traceJson` ثبت می‌کند تا کاربر مسیر محاسبه را در UI ببیند.

## ۶. قواعد تغییر و نسخه‌بندی

- فرمول‌های سیستم (`TS-*`, `ST-*`, `LB-*`) readonly در پروژه‌اند؛ کاربر **نسخه کپی** می‌گیرد و ویرایش می‌کند.
- غیرفعال‌سازی فرمول سیستمی مجاز است (مثلاً حذف مجاز در پروفایل خدماتی).
- هر فرمول فعال باید حداقل یک آزمون داده مرجع داشته باشد (TEST_MATRIX).
