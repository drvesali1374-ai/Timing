# کاتالوگ فرمول‌ها و زبان عبارتی (FORMULA CATALOG)

**نسخه:** ۱٫۱ (افزودن وضعیت اجرای فاز ۲ — بند ۷) — **تاریخ آخرین به‌روزرسانی:** ۳۱ اکتبر ۲۰۲۶
**قاعده صداقت:** هر فرمول دارای منبع نوع‌بندی‌شده است: `مرجع متدولوژیک` / `ریاضی محض` / `تعریف محصول`. مقدارهای پیش‌فرض ضرایب، «پیشنهاد قابل ویرایش» هستند نه استاندارد جهانی.

---

## ۱. قرارداد عمومی

- شناسه فرمول: `کلاس-شماره` (مثل `TS-011`)؛ هر فرمول `semver` دارد؛ تغییر → نسخه جدید، نه بازنویسی.
- **واحد پایه زمان:** ثانیه (SI) با دقت میلی‌ثانیه در محاسبات؛ تبدیل نمایشی به دقیقه/ساعت صرفاً لایه UI.
- خروجی هر ارزیابی: `{value, unit, status: valid|invalid|incomplete, errors[], trace, formulaVersion, inputRefs}`.
- قطعیت: ورودی یکسان + نسخه یکسان → نتیجه یکسان (توابع خالص، بدون زمان سیستم/تصادف تزریقی‌نشده).

## ۵. زبان عبارتی امن (DSL) — مشخصات v1

### ۵٫۱. اهداف
ارزیابی فرمول‌های تعریف‌شده کاربر در سطوح: مشاهده / عنصر / چرخه / مجموعه چرخه / گروه / پروژه / سناریو؛ بدون اجرای کد دلخواه.

### ۵٫۲. گرامر (EBNF فشرده)

```ebnf
expr        := or_expr ;
or_expr     := and_expr ( "||" and_expr )* ;
and_expr    := cmp_expr ( "&&" cmp_expr )* ;
cmp_expr    := add_expr ( ("=="|"!="|"<"|"<="|">"|">=") add_expr )* ;
add_expr    := mul_expr ( ("+"|"-") mul_expr )* ;
mul_expr    := unary ( ("*"|"/"|"%") unary )* ;
unary       := ("-"|"!")? primary ;
primary     := number | string | ident call? | "(" expr ")" | if_expr ;
if_expr     := "if" "(" expr "," expr "," expr ")" ;
call        := "(" args? ")" ;
args        := expr ( "," expr )* ;
ident       := [a-zA-Z_][a-zA-Z0-9_.]* ;
```

### ۵٫۳. توابع سفارتی مجاز (فهرست بسته)

| دسته | توابع |
|---|---|
| ریاضی | abs, min, max, round(x,d), floor, ceil, sqrt, pow |
| آمار/تجمیع | sum, mean, median, stddev, count, quantile |
| منطق/شرط | if, and, or, not, isMissing, coalesce |
| واحد | toUnit(x, unit) — فقط از UnitRegistry مجاز |
| زمان | duration(x, unit) |

**ممنوع:** حلقه، تخصیص متغیر، فراخوانی arbitrary، دسترسی به شبکه/DOM/زمان سیستم. عمق AST ≤ ۶۴؛ طول عبارت ≤ ۲۰۴۸ نویسه؛ تعداد گره ≤ ۵۱۲.

### ۵٫۴. جداسازی/مجوز نام‌ها
- شناسه‌های نقطه‌دار = پارامترها (`study.shift`) یا نتایج فرمول‌های دیگر (`TS-011.st`).
- هر شناسه به `inputContract` فرمول قید می‌شود؛ ارجاع ناموجود = خطای پیش از اجرا.

### ۵٫۵. تحلیل ایستا (پیش از ذخیره/اجرا)
۱. Parse → AST (بدون eval؛ پارسر بازگشتی-نزولی اختصاصی — ADR-03).
۲. بررسی نوع تقریبی (عدد/رشته/بولی/خلأ) + سازگاری واحد.
۳. ساخت **گراف وابستگی** فرمول‌ها؛ **چرخه → رد**.
۴. تقسیم بر صفر ثابت → هشدار؛ پویا → بررسی زمان اجرا با خطای مهارشده.

### ۵٫۶. وضعیت‌های ارزیابی
`valid` · `invalid` (خطای ساختاری/نوع/واحد/ارجاع) · `incomplete` (ورودی گمشده مانند ضریب تعیین‌نشده — محاسبه ممکن ولی خروجی وابسته «تأییدنشده» برچسب می‌خورد).

### ۵٫۷. Trace
هر ارزیابی درخت گام‌ها را با (شناسه گره، عمل، مقدار میانی، واحد) در `traceJson` ثبت می‌کند تا کاربر مسیر محاسبه را در UI ببیند.

## ۶. قواعد تغییر و نسخه‌بندی

- فرمول‌های سیستم (`TS-*`, `ST-*`, `LB-*`) readonly در پروژه‌اند؛ کاربر **نسخه کپی** می‌گیرد و ویرایش می‌کند.
- غیرفعال‌سازی فرمول سیستمی مجاز است (مثلاً حذف مجاز در پروفایل خدماتی).
- هر فرمول فعال باید حداقل یک آزمون داده مرجع داشته باشد (TEST_MATRIX).

## ۷٫ پیاده‌سازی فاز ۲ (وضعیت اجرا — ۳۱ اکتبر ۲۰۲۶)

> این بند وضعیت اجرای بندهای ۱ و ۵ همین سند را در فاز ۲ ثبت می‌کند. مشخصات §۵ تغییری نکرده؛ پیاده‌سازی مطابق همان مشخصات انجام شد. کد در `src/shared/formula/` (هسته مشترک خالص — ADR-011) زندگی می‌کند و هم سرور و هم UI آن را import می‌کنند؛ UI شرط‌های visibility/required فرم‌ساز را سمت کاربر با همین موتور ارزیابی می‌کند (منبع واحد ارزیابی).

### ۷٫۱. موتور و گرامر

- **پارسر بازگشتی-نزولی اختصاصی** مطابق گرامر EBNF بند ۵٫۲ **بدون انحراف** پیاده شد (lexer → parser → AST → تحلیل ایستا → ارزیاب؛ `engine.ts` قرارداد `parse → analyze → evaluate` را پیاده می‌کند).
- **فهرست توابع بسته** — هر ۲۲ تابع بند ۵٫۳ دقیقاً پیاده شده‌اند و هیچ تابع دیگری قابل فراخوانی نیست:

  | دسته | توابع پیاده‌شده (۲۲) |
  |---|---|
  | ریاضی (۸) | `abs` · `min` · `max` · `round(x,d)` · `floor` · `ceil` · `sqrt` · `pow` |
  | آمار/تجمیع (۶) | `sum` · `mean` · `median` · `stddev` (n−1) · `count` · `quantile` |
  | منطق/شرط (۶) | `if` · `and` · `or` · `not` · `isMissing` · `coalesce` |
  | واحد (۲) | `toUnit(x, unit)` (فقط واحدهای رجیستری) · `duration(x, unit)` |

- فهرست توابع برای UI از `GET /api/formula/functions` ارائه می‌شود (همان `FUNCTION_SIGNATURES`).
- **سقف‌ها اعمال و آزموده شدند:** عمق AST ≤ ۶۴ · تعداد گره ≤ ۵۱۲ · طول عبارت ≤ ۲۰۴۸ نویسه (ردِ فراتر از سقف در پارسر/تحلیل ایستا — آزمون واحد و یکپارچگی).
- **رشته‌های تزریق کد** (`eval('1+1')` · `require('fs')` · `process.exit(1)` · `globalThis` · `__proto__`) فقط خطای parse/ref تولید می‌کنند و **هرگز اجرا نمی‌شوند** — بدون eval/Function (ADR-003؛ آزمون R2-3).

### ۷٫۲. رجیستری واحدها (اجراشده)

| بُعد | واحدها | پایه |
|---|---|---|
| زمان | `ms` · `s` · `min` · `h` | ثانیه (SI) |
| طول | `mm` · `cm` · `m` · `km` | متر |
| تعداد | `pcs` | عدد |
| بی‌بُعد | `ratio` · (بدون واحد) | — |
| درصد | `percent` | — |

- **درصد بُعد مستقل خودش را دارد** تا ترکیب خام درصد با عدد/نسبت بدون تبدیل صریح (`toUnit(x,'ratio')`) خطای unit بگیرد — **تبدیل پنهان وجود ندارد**؛ درصد و بی‌بُعد فقط «هم‌خانواده مقیاس» برای toUnit شناخته می‌شوند.
- **ابعاد مشتق** مثل `s/pcs` (تاکت‌تایم TS-013) از تقسیم ساخته می‌شوند؛ جمع/مقایسه فقط با هم‌بُعد کامل.
- **قرارداد تعداد:** در ضرب، «تعداد» مضرب تکرار خنثی است — `42.5 s × 10 = 425 s`؛ اما در تقسیم، تعداد بُعد می‌ماند — تاکت: `27000 s ÷ 450 pcs = 60 s/pcs`. (مستند در `src/shared/formula/units.ts`.)

### ۷٫۳. وضعیت‌های ارزیابی و trace

- سه وضعیت بند ۵٫۶ پیاده شد: `valid` · `invalid` (خطای ساختاری/نوع/واحد/ارجاع با کد خطا) · `incomplete` (ورودی گمشده — محاسبه ممکن، خروجی وابسته برچسب «تأییدنشده» می‌خورد).
- **Trace** مطابق بند ۵٫۷ با (شناسه گره، عمل، مقدار میانی، واحد) ثبت و در `traceJson` جدول CalculationResult ذخیره می‌شود؛ **سقف ۲۵۶ گام** (زنجیره بلندتر فقط ۲۵۶ گام اول را ثبت می‌کند و با خطای limit اعلام می‌شود).

### ۷٫۴. نماد نتیجه فرمول‌ها (قرارداد اجرا)

- **کلید فرمول سفارشی:** الگوی `f.camelCase` — **بدون خط تیره**، چون گرامر DSL خط تیره ندارد و «a-b» تفریق تفسیر می‌شود (الگوی اعتبارسنجی: `^f\.[a-z][a-zA-Z0-9]*$`).
- **ارجاع به نتیجه فرمول‌های دیگر در عبارت:** `<کلید>.result`؛ کلیدهای سیستمی که خط تیره دارند به زیرخط تبدیل می‌شوند — `TS-011` در عبارت با **`TS_011.result`** ارجاع می‌شود (`formulaResultSymbol` در `shared/contracts/snapshot.ts`).
- شناسه‌های نقطه‌دار = پارامترها (به stableKey) یا نتایج فرمول‌ها؛ هر ارجاع به `inputContract`/جدول نمادها قید می‌شود و ارجاع ناموجود = خطای پیش از اجرا (تحلیل ایستا).

### ۷٫۵. فرمول‌های سیستمی در پروژه (اجراشده)

- کتابخانه سیستمی **۲۲ فرمول** (TS/ST/LB) با عبارت اجرایی + `inputContract` در snapshot v2 پروفایل‌ها عرضه می‌شود (`src/modules/profiles/definitions/formula-library.ts`).
- **فقط‌خواندگی فرمول سیستمی:** ویرایش عبارت با **۴۰۳** رد می‌شود؛ **غیرفعال‌سازی (deprecated) مجاز است**؛ برای ویرایش، کاربر **کپی سفارشی** با `origin:custom` می‌گیرد (بند ۶).
