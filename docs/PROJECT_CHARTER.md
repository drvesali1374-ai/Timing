# منشور محصول (PROJECT CHARTER)

**پروژه:** پلتفرم ماژولار زمان‌سنجی صنعتی، مطالعه کار، نمودارهای فرایندی و بالانس خط تولید
**نام کد:** Timing
**نسخه سند:** ۱٫۰ (فاز صفر)
**تاریخ:** ۲۹ اکتبر ۲۰۲۶
**مرجع الزامات:** `industrial_time_study_master_spec_fa.md` (سند جامع، نسخه ۱٫۰)
**زبان محصول:** فارسی (RTL) با معماری آماده چندزبانه

---

## ۱. مأموریت

ساخت یک وب‌اپلیکیشن حرفه‌ای، ماژولار و توسعه‌پذیر که از **زمان‌سنجی مستقیم با کرنومتر** آغاز می‌شود و به بستری جامع برای مطالعه کار، تحلیل فرایند، تعیین **زمان نرمال و استاندارد**، طراحی و تحلیل **نمودارهای فرایندی OPC/FPC**، **بالانس خط تولید** و **برآورد نیروی کاری** تبدیل می‌شود.

محصول نباید صرفاً یک کرنومتر، فرم ثابت، داشبورد نمایشی یا مجموعه‌ای از فرمول‌های تغییرناپذیر باشد. موفقیت یعنی کاربر بتواند **بدون تغییر کد**، برای هر پروژه، ساختار داده و روش محاسباتی متناسب با فعالیت خود تعریف کند؛ در حالی که در اولین استفاده نیز با سیستم خالی و بی‌راهنما روبه‌رو نشود.

## ۲. قلمرو محصول

### ۲.۱. داخل قلمرو نسخه پایه (فازهای ۰ تا ۷)

| حوزه | شرح |
|---|---|
| مدیریت پروژه | ایجاد، ویرایش، کپی، بایگانی، جست‌وجو، فیلتر، تاریخچه نسخه‌ها |
| پیکربندی پویا | خانواده‌ها و پارامترهای سفارشی با انواع داده گسترده، فرم‌ساز پویا |
| موتور فرمول | زبان عبارتی محدود و امن، چند سطح محاسبه، گراف وابستگی، trace |
| مدل فرایند | فعالیت/عنصر کاری مشترک با انواع زمان (دستی، ماشینی، انتظار و…) |
| نمودارهای OPC/FPC | ویرایشگر بصری با اعتبارسنجی، مقایسه روش فعلی/پیشنهادی، خروجی چاپی |
| دستیار آفلاین نمودار | موتور قواعد قطعی + کتابخانه دانش محلی؛ مدل زبانی محلی اختیاری |
| موتور کرنومتر | زمان‌سنجی پیوسته/بازگشت به صفر، چرخه‌ها، وقفه‌ها، بازیابی، صف آفلاین |
| تحلیل آماری | آمار توصیفی، داده پرت، تفکیک گروهی، کفایت نمونه، زنجیره زمان نرمال/استاندارد |
| بالانس خط | الگوریتم‌های LCR/RPW/Kilbridge–Wester، Yamazumi، سناریو، برآورد نیرو |
| گزارش‌ها | خلاصه پروژه، مشاهدات، تحلیل، بالانس؛ خروجی CSV/Excel/PDF با حفظ RTL |
| آفلاین | PWA/ذخیره محلی برای ثبت و مشاهده ضروری؛ صف همگام‌سازی با حل تعارض |

### ۲.۲. خارج از قلمرو نسخه پایه (افزونه‌های آتی مگر با دلیل روشن در فاز صفر)

- اتصال زنده به PLC / MES / ERP
- شناسایی خودکار با بینایی ماشین
- سخت‌افزار تخصصی و تجهیزات اندازه‌گیری خارجی
- مدیریت کامل منابع انسانی (HR) و حقوق و دستمزد
- زمان‌بندی پیشرفته کارخانه (APS)
- همگام‌سازی ابری چندسازمانی با اشتراک هم‌زمان

برای ایده‌های توسعه‌ای ارزشمند پس از نسخه پایه (آزمایشگاه سناریو، پروفایل سازمانی، تحلیل حساسیت و…) به بخش F سند جامع و `docs/KNOWN_LIMITATIONS.md` مراجعه شود.

## ۳. اصول ثابت غیرقابل مذاکره

### ۳.۱. پیش‌فرض مهندسی‌شده + شخصی‌سازی حداکثری
- در ایجاد پروژه، پروفایل‌های روش‌شناختی آماده پیشنهاد می‌شود و یک پروفایل عمومیِ عملیاتی **از ابتدا انتخاب شده** است.
- پروفایل پیش‌فرض باید خانواده‌ها، پارامترهای پایه، چرخه تحلیل، فرمول‌های معتبر و مستند، فرم‌ها و خروجی‌های اصلی را داشته باشد — نام و ظاهر از پیش‌ساخته کافی نیست.
- کاربر می‌تواند هر بخش را بپذیرد، ویرایش کند، غیرفعال کند یا با نسخه خود جایگزین کند.

### ۳.۲. صداقت روش‌شناختی (اصل ضد-جعل استاندارد)
- **هیچ استاندارد واحد و جهان‌شمولی** برای تمام روش‌های زمان‌سنجی، تمام صنایع و همه توافق‌های سازمانی فرض نمی‌شود.
- اصول مرجع (متون ILO/REFA)، استانداردهای رسمی (ISO) و مقدارهای پیشنهادی/وابسته به کارخانه **از هم جدا** نگه داشته می‌شوند.
- ضرایب وابسته به صنعت، توافق کارفرما/کارگر، شیفت و شرایط محیطی بدون منبع و فرض روشن، «استاندارد جهانی» معرفی نمی‌شوند.
- اگر ضریبی تعیین نشده باشد، محاسبات پایه انجام می‌شود اما خروجی وابسته با برچسب «تأییدنشده/نیازمند تعیین مقدار» نمایش داده می‌شود.
- «بهینه قطعی»، «دقت زمان» و «هوشمندی آفلاین» بیش از آنچه واقعاً پیاده‌سازی و اثبات شده ادعا نمی‌شود.

### ۳.۳. استقلال پروژه‌ها
- هر پروژه یک فضای کاری مستقل است. ویرایش یک پروژه **هیچ** پروژه دیگری را تغییر نمی‌دهد.
- کپی از الگو/پروژه دیگر، نسخه مستقل و قابل ردیابی ایجاد می‌کند (Copy-on-Instantiate).
- هر عملیات خواندن/ویرایش/حذف در سمت سرور مجوزسنجی می‌شود؛ مخفی‌کردن در UI کافی نیست.

### ۳.۴. مرجع حقیقت و قابلیت ردیابی
- داده خام از داده تبدیل‌شده، مشتق‌شده و خروجی گزارش جدا نگه داشته می‌شود.
- هر نتیجه مهم به پروژه، نسخه پیکربندی، نسخه تعریف پارامتر، نسخه فرمول، شناسه مشاهدات ورودی، واحدها و زمان محاسبه قابل ارجاع است.
- تغییر فرمول، نتایج قبلی را بی‌سروصدا جایگزین نمی‌کند؛ «محاسبه مجدد» نسخه جدید می‌سازد یا تغییر را ثبت می‌کند.

### ۳.۵. ایمنی و امنیت
- اجرای مستقیم کد دلخواه کاربر (eval) در فرمول‌ها **ممنوع** است.
- ارجاع نامعتبر، چرخه وابستگی، تقسیم بر صفر، نوع/واحد ناسازگار و داده ناقص کشف و گزارش می‌شوند.
- رویدادهای حساس قابل ممیزی هستند؛ حذف/اصلاح داده اندازه‌گیری کنترل‌شده است.
- در حالت آفلاین، تعارض و ثبت تکراری مدیریت می‌شود.
- دقت کرنومتر در شرایط خواب دستگاه/تب پس‌زمینه بیش از واقع ادعا نمی‌شود.

### ۳.۶. فارسی و RTL
- رابط فارسی و راست‌به‌چپ در چیدمان، نمادگذاری، فرم‌ها، نمودارها و جداول باید درست کار کند.
- جهت جریان یک نمودار نباید فقط به علت RTL بودن صفحه برعکس شود.
- مقدار ذخیره‌شده زمان استاندارد و بدون ابهام می‌ماند؛ تقویم جلالی صرفاً لایه نمایشی است.

## ۵. معیارهای موفقیت محصول (خلاصه؛ شرح کامل در `docs/TEST_MATRIX.md`)

۱. پروژه جدید با پروفایل پیش‌فرض **واقعی و قابل استفاده** ساخته شود.
۲. کاربر بدون تغییر کد، خانواده/پارامتر سفارشی تعریف، مقدار ثبت و در فرمول/گزارش استفاده کند.
۳. ویرایش یک پروژه هیچ تغییر ناخواسته‌ای در پروژه دیگر ایجاد نکند.
۴. کرنومتر از شمارنده ساده ثانیه‌ای استفاده نکند و اختلال‌ها را شفاف مدیریت کند.
۵. ویرایشگر OPC/FPC خروجی تصویری/چاپی خوانا و قابل ویرایش تولید کند.
۶. دستیار نمودار بدون اینترنت، قابلیت‌های قطعی راهنمایی و اعتبارسنجی داشته باشد.
۷. الگوریتم‌های بالانس قیود تقدم/تأخر را نقض نکنند یا نقض را صریح گزارش کنند.
۸. تفاوت زمان مشاهده‌شده، نرمال، استاندارد، چرخه و تاکت درست حفظ شود.
۹. نتایج محاسباتی به داده و نسخه فرمول قابل ردیابی باشند.
۱۰. تست‌ها واقعاً اجرا و نتایج آن‌ها ثبت شوند؛ هیچ بخش کلیدی با داده نمایشی وانمود به تکمیل‌شدن نکند.

## ۶. محدودیت‌های هدایت‌گر طراحی

- **آفلاین-محور واقعی:** محل استفاده (کارخانه) اغلب اینترنت ناپایدار دارد؛ قابلیت‌های ضروری ثبت/مشاهده باید آفلاین کار کنند.
- **مرورگر-محور:** محصول در مرورگرهای مدرن دسکتاپ و تبلت اجرا می‌شود؛ سخت‌افزار اختصاصی در نسخه پایه نیست.
- **حریم خصوصی:** شرح کار، عملکرد کارکنان و اطلاعات تولید بدون مجوز صریح به سرویس بیرونی ارسال نمی‌شود.
- **هزینه اجرای مدل محلی:** اجرای LLM در مرورگر (WebGPU) فقط لایه اختیاری است و نباید پیش‌نیاز قابلیت پایه باشد.

## ۷. حکم‌های کلیدی فاز صفر (خلاصه؛ مستندات کامل در ADR)

| موضوع | تصمیم | سند |
|---|---|---|
| سبک معماری | Modular Monolith با مرزهای ماژول صریح | ADR-001 |
| فناوری پایه | Next.js 16 (App Router) + TypeScript + Tailwind 4 + shadcn/ui | ADR-002 |
| داده و نسخه‌بندی | Prisma + SQLite؛ نسخه‌بندی Snapshot غیرقابل تغییر برای پیکربندی | ADR-005 |
| موتور فرمول | DSL امن با Parser/AST اختصاصی (بدون eval) | ADR-003 |
| زمان‌سنجی | تفکیک زمان monotonic (`performance.now()`) از زمان دیواری | ADR-004 |
| آفلاین | PWA + IndexedDB + صف همگام‌سازی با کلید idempotent | ADR-006 |
| ویرایشگر نمودار | React Flow (`@xyflow/react` v12) برای فاز ۳ | ADR-007 |
| بالانس خط | LCR + RPW + Kilbridge–Wester؛ رابط افزونه برای حل‌گرهای آتی؛ بدون MILP در پایه | ADR-008 |
| کنترل دسترسی | RBAC با مجوزسنجی سمت سرور روی همه APIها | ADR-009 |
| پارامترهای پویا | جداسازی تعریف/مقدار + ذخیره JSON ساخت‌یافته (بدون ستون فیزیکی برای هر پارامتر) | ADR-010 |

## ۸. اصل «تست بدون شاهد، پذیرفته نیست»

عبارت «پیاده‌سازی شد» بدون آزمون اجراشده، خروجی قابل بررسی یا توضیح مستند، پذیرش محمول نمی‌شود. وضعیت هر معیار در `docs/PHASE_STATUS.md` به‌صورت «قبول با شاهد / قبول با محدودیت / رد-ناتمام» گزارش می‌شود.
